# 数据流程与关键逻辑

本文描述当前原型的实现，不表示路线、天气或统计结果已经经过独立准确性评估。

## 交互网页中的实时路线

1. 用户在网页填写起点、目的地、可选途经点、城市范围、路线偏好和出发时间。
2. 对文本地址，网页通过高德地点提示/地理编码查询候选；用户确认候选后，程序才使用其坐标。浏览器定位是可选项，需要用户授权。
3. 程序把坐标、途经点顺序和路线策略交给高德驾车规划服务。
4. 页面展示高德返回的路线耗时、距离、收费、分段导航动作和查询时的路况。路线比较以高德返回的第一条路线为基准，差值由程序直接计算。
5. 若是符合记录条件的实时查询，程序尝试把路线几何、策略、地点和采样时间写入本机 SQLite 历史库。数据库不可用时仍尽可能显示已经取得的实时路线，并提示历史记录问题。

路线耗时是地图服务的估算，不是车辆实际行驶时间；路况是查询时状态，不是未来时刻预测。地理编码、驾车规划、POI 等高德能力要求对应 Web 服务权限可用。

## 未来时间历史参考

用户选择未来时间后，程序按起终点、途经点顺序、路线策略、星期和相近时段查询本地历史样本。每条路径用路线几何识别，不单靠“路线 1/2/3”的返回序号。符合条件的记录先按日期汇总，再跨日期计算中位数；样本少于三个不同日期时不提供估算。

这个功能只统计过去查询到的地图预计值。它不建模事故、天气、施工等因素，也不能推断未来实际交通。路线几何改变时可能无法匹配旧样本，旧格式记录不会被强行归到新路径。

## 定时简报

定时脚本读取本机配置和加密保存的 Key，分别请求天气和路线数据。每个服务分别处理失败：天气失败时仍可保留路线，路线失败时仍可保留天气；两者都不可用时生成带诊断说明的报告并以非零状态结束。OpenAI 摘要是可选步骤：没有 Key 或摘要服务异常时，程序用本地规则整理已有事实。摘要只能组织输入数据，不能使缺失数据变成已知事实。

## 离线演示

`commute_web.py --demo` 进入单独的演示处理器，使用代码内的固定合成路线。该模式不读取 API Key、不调用外部服务、不写入历史数据库。演示中的所有数字和路况均为虚构。

## Key 与隐私边界

- 高德 Web 服务 Key 用于地点、路线与设施查询；OpenAI Key 只用于简报文字生成。
- Key 从进程环境或 Windows 当前用户保护的本地存储读取，不应写入代码、配置示例、报告、截图或 Git。
- 路线历史保存在运行电脑的 `commute_history.sqlite3`；它包含地点/路线样本，需按个人数据妥善保管。
- 分享调试信息前，移除 Key、精确住址、个人坐标、邮箱、浏览器令牌和本机用户名/文件路径。
